# Гуляй Город

Flutter-приложение для городских маршрутов на PocketBase. Основные платформы проекта — Android и iOS. В коде используются Flutter, BLoC, PocketBase и feature-first структура.

## Текущее состояние

- Реализованы onboarding, вход по email или телефону, регистрация, восстановление пароля по email, выбор и изменение фото профиля.
- PocketBase хранит сессию через системное защищённое хранилище; существующая сессия из SharedPreferences переносится туда при следующем запуске.
- Есть светлая и тёмная темы с сохранением выбора.
- Опубликованные маршруты читаются из PocketBase; пользователь может начать маршрут, проходить GPS-контрольные точки последовательно и завершить маршрут у финиша.
- PocketBase hooks повторно проверяют точность GPS (до 25 м), геозону (радиус задаётся у маршрута, 5–100 м, обычное значение — 30 м), порядок точек и скорость между подтверждениями. Завершение, изменение баланса и транзакция награды выполняются атомарно; клиент не может записывать посещения или редактировать баланс.
- Карта использует OpenStreetMap и показывает только базовую карту Новокузнецка. GPS запрашивается только во время активного маршрута.
- Магазин отключён. QR-код отображается как заглушка.
- Баллы нельзя менять из мобильного клиента. Каждое прохождение может создать только одну транзакцию награды.

## Запуск PocketBase локально

Требуются `curl` и `unzip`. Скрипт загружает PocketBase v0.40.6 в `.tools/pocketbase/`, применяет миграции и запускает его с данными в `.local/pocketbase-data/`. Эти локальные файлы игнорируются Git.

```sh
./scripts/setup-pocketbase.sh
```

Первый запуск применит миграции из `pb_migrations/`. Откройте `http://127.0.0.1:8090/_/` и создайте локальную учётную запись суперпользователя. Не используйте её в приложении и не добавляйте пароль в репозиторий.

Чтобы запустить Flutter на Android-эмуляторе, где `127.0.0.1` указывает на сам эмулятор:

```sh
flutter run --dart-define=POCKETBASE_URL=http://10.0.2.2:8090
```

Для iOS Simulator и desktop по умолчанию используется `http://127.0.0.1:8090`. Для физического устройства задайте доступный в локальной сети адрес компьютера через `--dart-define=POCKETBASE_URL=...`; для развёрнутого backend используйте HTTPS.

`POCKETBASE_LISTEN` задаёт интерфейс сервера, например `0.0.0.0:8090` для доступа из локальной сети. Не открывайте такой адрес в интернет без HTTPS, firewall и отдельной серверной настройки.

## Схема и правила доступа

Миграция создаёт:

- `users` — встроенная PocketBase auth collection: email, имя, телефон, аватар, баланс и статистика. Пользователь видит только свой профиль и не может менять баланс, роль или серверную статистику.
- `routes` — опубликованные маршруты доступны для чтения; создание, изменение и публикация доступны только суперпользователю. У маршрута есть `checkpoint_radius_m`.
- `route_checkpoints` — упорядоченные координаты точек маршрута, включая финиш. Клиент читает их только у опубликованных маршрутов и не может менять.
- `route_completions` — пользователь может создать своё прохождение `in_progress`, но не завершить, изменить или удалить его.
- `route_checkpoint_visits` — серверный журнал GPS-посещений; запись, изменение и удаление закрыты для клиента. Есть уникальность пары прохождение/точка.
- `point_transactions` — владелец читает историю; запись и изменение доступны только серверу. Уникальный ключ и связь не допускают повторной награды за одно прохождение.

Миграции создают схему без тестовых маршрутов и пользователей. Чтобы добавить одну явно помеченную демо-запись и три условные GPS-точки для разработки, задайте переменные суперпользователя и выполните:

```sh
POCKETBASE_SUPERUSER_EMAIL=... POCKETBASE_SUPERUSER_PASSWORD=... node scripts/seed-demo-routes.mjs
```

Демо-маршрут называется «ДЕМО · Прогулка по Новокузнецку», а описания помечают точки как условные. Это не туристическая рекомендация; удалите демо-набор перед подготовкой production-данных. Остальные маршруты добавляйте через PocketBase Dashboard. Схему полей и API Rules можно посмотреть в `pb_migrations/1770000000_initial_schema.js`.

Обработчики `pb_hooks/route_progress.pb.js` предоставляют аутентифицированные endpoints `/api/gorod/route-progress/checkpoint` и `/api/gorod/route-progress/finish`. Для создания маршрута задайте у каждой точки возрастающий `sequence`, начиная с 1, и отметьте последнюю `is_finish=true`. У маршрута установите радиус проверки. Только второй endpoint завершает прохождение и начисляет награду после повторной серверной GPS-проверки.

Для локальной проверки серверной GPS-логики используйте:

```sh
POCKETBASE_SUPERUSER_EMAIL=... POCKETBASE_SUPERUSER_PASSWORD=... node scripts/test-pocketbase-gps.mjs
```

Скрипт создаёт временного пользователя и тестовый маршрут, проверяет неточный GPS, перескок и повтор точки, раннее завершение, запрет прямой записи баланса и посещений, атомарную награду и идемпотентный повтор. Созданные записи удаляются по завершении. Координаты отправляются через HTTP и имитируют GPS; физическая геолокация проверяется только на устройстве.

Восстановление пароля сейчас доступно только для учётных записей с email, поскольку штатная процедура PocketBase отправляет письмо. Для восстановления по телефону нужен отдельный согласованный SMS-провайдер.

## Карта

Карта использует стандартные тайлы OpenStreetMap, без геолокации, линий маршрутов и маркеров. Источник указывается на карте. Для производственной нагрузки необходимо согласовать подходящий tile provider или хостинг тайлов и соблюдать ограничения публичного сервера OSM.


## Проверка

```sh
flutter analyze
flutter test
```

Для сквозного сценария на iOS Simulator запустите локальный PocketBase и добавьте демо-маршрут из раздела выше, затем выполните:

```sh
flutter drive \
  --driver=test_driver/integration_test.dart \
  --target=integration_test/registration_flow_test.dart \
  -d <SIMULATOR_UDID> \
  --dart-define=POCKETBASE_URL=http://127.0.0.1:8090
```

Тест проходит регистрацию, вход, восстановление доступа, основные вкладки, редактирование профиля, переключение темы и завершение демо-маршрута через реальные PocketBase endpoints. Координаты для воспроизводимой проверки геозоны подаются тестовым Geolocator-адаптером; на самом устройстве используется `geolocator`. Прогон создаёт тестового пользователя, прохождение, посещения точек и транзакцию награды в локальной базе; удалите эти записи через PocketBase Dashboard после проверки.

Скриншоты последнего прогона находятся в `artifacts/simulator/`.
